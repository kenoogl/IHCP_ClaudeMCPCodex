# Polynomial前処理の実装可能性評価レポート

**評価日**: 2025年10月13日
**ステータス**: ❌ **実装中止**
**理由**: Jacobi前処理の失敗により、効果が見込めないと判断

---

## 1. 評価の背景

### Phase 1-Cの結果
- **Jacobi前処理**: 収束性不良（GS比12倍以上遅い）
- **原因**: 対角前処理のみでは不十分
- **教訓**: この熱伝導問題には対角要素だけでは効果が薄い

### 多項式前処理の検討
Phase 1-Cの結果を受けて、次の前処理候補として多項式前処理の実装可能性を評価。

---

## 2. 多項式前処理の概要

### 2.1 Neumann展開

**アルゴリズム**:
```
M^{-1} ≈ D^{-1} ∑_{k=0}^{m-1} (I - D^{-1}A)^k
```

**特徴**:
- 基盤: **Jacobi対角前処理 D^{-1}**
- マトリクスフリー
- 固定係数（実装が単純）

**実装コスト**: 3-5日
- 新規関数: 3個（対角前処理、Neumann更新、axpy）
- 既存CalcAX!の再利用

**期待効果**: 10-25%改善（条件付き）
- Jacobiの2-3倍の効果（理論値）
- **但しスペクトル半径ρ < 1が必要**

**リスク**: 🔴 **高**
- Jacobi前処理が失敗した問題で成功する可能性は低い
- ρ ≥ 1の場合は発散
- 固有値推定の追加実装が必要

---

### 2.2 Least-Squares多項式

**アルゴリズム**:
```
p_m(A) を ||I - p_m(A)A|| 最小化で決定
```

**特徴**:
- 係数を最小二乗問題で最適化
- Neumannより安定

**実装コスト**: 1-2週間
- Krylov部分空間法
- 最小二乗ソルバー
- 係数計算とキャッシュ

**期待効果**: 20-35%改善
- Neumannより高い効果

**リスク**: 🟡 **中**
- 実装が複雑
- デバッグに時間

---

## 3. 実装可能性の評価

### 3.1 技術的実装可能性

**既存コードの再利用性**: ✅ **高**
- マトリクスフリーCalcAX!が利用可能
- 前処理APIが拡張しやすい設計（Val型ディスパッチ）
- 並列実行バックエンド完備

**実装の難易度**:
- Neumann展開: 🟢 **低～中**（3-5日）
- Least-Squares: 🔴 **高**（1-2週間）

---

### 3.2 効果の見込み

**理論的効果**: 🟡 **条件付き**

| 前処理 | 基盤 | 期待効果 | 条件 |
|--------|------|---------|------|
| Jacobi | 対角D^{-1} | ❌ **失敗** | - |
| Neumann | 対角D^{-1} | 10-25%? | ρ < 1 |
| Least-Squares | 多項式最適化 | 20-35%? | 広範なスペクトル |

**重要な考察**:
- Neumann展開の基盤は**Jacobi対角前処理**
- Phase 1-CでJacobiが**12倍以上遅い**という結果
- **対角前処理ベースの手法は効果が薄い**と判明

→ **Neumannも成功の見込みは低い** ⚠️

---

### 3.3 コスト対効果分析

| 項目 | Neumann | Least-Squares |
|-----|---------|--------------|
| **実装工数** | 3-5日 | 1-2週間 |
| **期待効果** | 10-25%（条件付き） | 20-35%（不確実） |
| **リスク** | 高（発散の可能性） | 中（実装の複雑さ） |
| **成功確率** | 🔴 **低（20-30%）** | 🟡 **中（40-50%）** |

**Jacobi失敗の影響**:
- 対角前処理が効かない問題と判明
- Neumannの成功確率: **20-30%以下**
- 実装コストに見合わない

## 4. 結論と推奨アクション

### 4.1 評価結果

**総合判定**: ❌ **実装中止**

**理由**:
1. **Jacobi前処理の失敗**: Phase 1-Cで対角前処理が効かないことが判明
2. **低い成功確率**: Neumann（20-30%）、Least-Squares（40-50%）
3. **コスト対効果**: 実装工数に見合わない
4. **機会コスト**: Phase 2（並列化）の方が確実に効果がある

---

## 6. 参考情報

### 6.1 現在のコードアーキテクチャ

**前処理API**（優れた設計）:
```julia
smoother_val = smoother_selector(smoother)  # Symbol → Val変換
Preconditioner!(... , smoother_val, ...)     # 公開API
  → _Preconditioner!(... , ::Val{:gs}, ...)  # 内部実装（多重ディスパッチ）
```

**利用可能なsmoother**:
- `:none` - 恒等変換
- `:gs` - Gauss-Seidel法（デフォルト、最良）
- `:jacobi` - Jacobi法（Phase 1-C、不採用）

**マトリクスフリー実装**:
- `CalcAX!`: 行列ベクトル積（7点ステンシル）
- `apply_jacobi_diag!`: 対角前処理（Jacobi用）

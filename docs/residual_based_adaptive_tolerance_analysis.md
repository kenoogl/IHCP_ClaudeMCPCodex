# 残差履歴ベース適応的収束判定の分析

**作成日時**: 2025年10月14日
**状況**: Phase 1-E完了後の追加検討

---

## 📋 目的

Phase 1-Eで実装した「解の相対変化ベース」の適応的収束判定に対して、
adaptive_tolerance.mdで提案されている「残差履歴ベース」の方法を検討し、
実装可能性と期待効果を評価する。

---

## 📊 Phase 1-Eの現状分析

### ✅ 達成した成果

- **総改善**: -6.37%（898.41秒 → 841.20秒）
- **Adjoint solverで最大効果**: -12.87%
- **精度維持**: 温度場誤差は無視できるレベル

### ⚠️ 観察された課題

Phase 1-Eでは一部のステップで反復回数が**増加**（悪化）している：

| ソルバー | ステップ | 悪化率 |
|---------|---------|--------|
| DHCP | t=5 | +29.5% |
| DHCP | t=7 | +70.9% ⚠️ |
| Adjoint | t=7 | +8.5% |
| Adjoint | t=2 | +4.8% |
| Sensitivity | t=3 | +18.1% |
| Sensitivity | t=5 | +24.8% |

**原因の仮説**:
1. 適応的tolが過剰に緩和されている（kappa_theta = 0.2が大きすぎる）
2. 解の相対変化量が必ずしも線形ソルバーの収束性を反映していない
3. warmup期間が不適切（ソルバー別の最適値が異なる）

---

## 🔬 2つの適応的方法の比較

### 方法1: 解の相対変化ベース（現在の実装）

#### アルゴリズム
```
δₙ = ||θⁿ - θⁿ⁻¹||₂ / (||θⁿ||₂ + ε)
tolₙ = clamp( κ_θ · δₙ, tol_min, tol_max )
```

#### メリット ✅
1. **物理的意味が明確**: 温度場の変化を直接評価
2. **実装が簡単**: 既に温度場データを持っている
3. **スケール不変**: 相対変化量なので温度の絶対値に依存しない
4. **理論的裏付け**: Elman et al. (2014)が推奨

#### デメリット ❌
1. **線形ソルバーとの乖離**: 温度場変化が小さくても線形系が難しいケースで過剰緩和
2. **タイミングの問題**: 前ステップの温度場から次ステップのtolを決定（1ステップ遅延）
3. **ソルバー別最適化が困難**: DHCP/Adjoint/Sensitivityで同じ基準を使用

---

### 方法2: 残差履歴ベース（提案）

#### アルゴリズム
```
tolₙ = clamp( κ_r · ρ̄_{n-1}^α, tol_min, tol_max )
```
- `ρ̄_{n-1}`: 前ステップの最終残差ノルム（移動平均）
- `κ_r ≈ 0.5`
- `α ∈ [0.5, 1.0]`（残差の影響度調整）

#### メリット ✅
1. **線形ソルバーの収束性を直接反映**: 前ステップで収束が遅ければ次も厳しく
2. **Eisenstat-Walker理論に直接対応**: inexact Newton法の標準的アプローチ
3. **ソルバー別最適化が容易**: DHCP/Adjoint/Sensitivityで独立したパラメータ設定可能
4. **実績がある**: PETSc、Trilinos、deal.IIなどで標準実装

#### デメリット ❌
1. **実装の複雑さ**: PBiCGSTAB!の戻り値に最終残差ノルムを追加する必要がある
2. **スケール依存**: 残差ノルムの絶対値が問題ごとに異なる
3. **物理的意味が薄い**: 残差は数学的な量で、温度場の変化と直接関係しない
4. **チューニングが必要**: α, κ_r の最適値は問題依存

## 🛠️ 実装に必要な変更

### 現在のPBiCGSTAB!の戻り値

```julia
# CommonSolver.jl: line 216
return isconverged, itr, res0
```

- `res0`: **初期残差ノルム**（最終残差ではない）❌

### 必要な修正

```julia
# CommonSolver.jl の修正案
return isconverged, itr, res0, res_final
```

- `res_final`: **最終残差ノルム**（ループ最後のresを返す）✅

#### 影響範囲

PBiCGSTAB!を呼び出している全ソルバーの修正が必要：
1. `DHCPSolver.jl`: `multiple_time_step_solver_DHCP()`
2. `AdjointSolver.jl`: `multiple_time_step_solver_Adjoint()`
3. `SensitivitySolver.jl`: `multiple_time_step_solver_Sensitivity()`

**推定工数**: 2-3時間（実装）+ 1時間（テスト）

## 📚 理論的補足

### Eisenstat-Walker戦略との関係

Eisenstat-Walker (1996)の提案：
```
tolₙ = γ · ||F(xⁿ⁻¹)||^α / ||F(xⁿ⁻²)||
```

この戦略は**Newton法の外側ループ**（非線形反復）に対する内側ループ（線形ソルバー）の収束基準を決定します。

**我々の問題との違い**:
- IHCPは時間発展問題（各ステップは独立した線形問題）
- Newton法の反復ではない
- したがって、残差履歴ベースは直接適用できない
- **解の相対変化ベース**の方が理論的に適切

### 時間離散化誤差との整合

Knoll & Keyes (2004)の推奨：
```
tolₙ ~ O(Δt^{p+1})
```

**我々の問題での適用**:
- 時間刻みΔtが一定（1ms固定）
- したがって、時間刻み依存の戦略は不要
- **解の相対変化**が時間離散化誤差を間接的に反映

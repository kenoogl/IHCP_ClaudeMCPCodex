## 🔍 分析と結論

### 主要な発見

1. **Julia版のPBICGSTABは極めて高効率**
   - Python版（SciPy CG）に比べて、**1.88〜10.66倍少ない反復回数**で収束
   - 特にAdjoint/Gradientソルバーで顕著（10.66倍）

2. **Adjoint/Gradientソルバーの差が最大**
   - Python版: 平均78.3反復/ステップ
   - Julia版: 平均7.0反復/ステップ
   - **11.2倍の効率差**

3. **全体の線形ソルバー反復回数**
   - Python版: 5638反復（全ウィンドウ、CGM2回分）
   - Julia版: 964反復（全ウィンドウ、CGM2回分）
   - **Python版が5.85倍多い反復を実行**

4. **ウィンドウサイズと反復回数の関係**
   - 小さいウィンドウほどPython版の反復回数が減少傾向
   - Julia版は安定して少ない反復回数を維持

### なぜPython版の方が速いのか？

**矛盾**: Julia版の線形ソルバーは5.85倍少ない反復で収束するのに、全体では4.09倍遅い

**仮説**:

1. **1反復あたりの計算時間**
   - Python版: SciPyの高度に最適化されたCコード（BLAS/LAPACK）
   - Julia版: カスタムPBICGSTAB実装（並列化あり）
   - **1反復あたりの時間がJulia版で長い可能性**

2. **並列化のオーバーヘッド**
   - Julia版: FLoops並列化のオーバーヘッド
   - 小さな問題サイズでは並列化の利益が少ない

3. **Python版の熱流束がゼロ問題**
   - **重要**: Python版は収束していない可能性が高い
   - 線形ソルバーは動作しているが、CGMアルゴリズム全体が失敗している
   - つまり、「速い」が「不正確」

### 結論

- **線形ソルバーの効率**: Julia版（PBICGSTAB）が圧倒的に優秀（5.85倍少ない反復）
- **全体の実行速度**: Python版が4.09倍速い
- **計算の正確性**: Julia版のみ正しい結果（熱流束が妥当な範囲）

**最終判定**: 線形ソルバーの反復回数ではJulia版が圧勝しているが、全体の実行時間とCGMアルゴリズムの収束性を考慮すると、**Python版に問題がある可能性が非常に高い**。

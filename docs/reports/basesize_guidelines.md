## 1. 背景

FLoops の `basesize` は、スレッドに割り当てる最小チャンクサイズ（ループ反復数）を制御するパラメータである。  
小さすぎるとスケジューリング／同期のオーバーヘッドが支配的になり、大きすぎるとスレッド間の負荷が偏って並列効率が落ちる。最適値は問題規模・スレッド数・時間ステップ数（nt）などの条件で決まる。

---

## 2. 既存測定から得られた知見

### 2.1 格子 80×100×20・nt=10 の場合
- Step1（DHCP）および Step2（CGM）ともに **4スレッド×basesize=600 が最速**（DHCP: 4.88 s、CGM: 11.86 s）。
- basesize が **400〜600** の範囲であれば性能差は ±3% 程度。  
- basesize ≥1000 で性能が急激に悪化（+30〜120%）。  
- 8 スレッドを設定しても 4コア CPU では 4 スレッド時より遅い。

### 2.2 nt 依存性（nt=10/30/50/100）
- 実行時間は nt にほぼ比例して伸びるが、**最適 basesize は 400〜700 に留まる**。  
- nt=30 では basesize=700 がわずかに速いが、basesize=600 と 2–3% の差。  
- **basesize=600 を“汎用推奨値”にできる**（nt=100 でも最速）。

### 2.3 スライディングウィンドウ（window=5, overlap=2, CGM2反復）
- 小ウィンドウ構成では **basesize=500** が最速（34.34 s）。  
- base size を 1000 以上にすると、他フェーズ同様に顕著な性能低下。  
- ウィンドウ境界処理などの追加オーバーヘッドはあるが、最適帯は 400〜600 付近に収まる。

---

## 3. 最適 basesize を支配する主因

1. **総要素数 N（空間格子）**  
   - 最適値はおおむね `N / (threads × 60～70)` に相当。  
   - 16 万セル・4 スレッドでは basesize ≈ 600 が最速。

2. **スレッド数**  
   - スレッドが多いほど basesize を小さめにしてチャンク数を稼ぐ必要がある。  
   - 4 コアで 8 スレッドを使ってもオーバーヘッドが増えるだけで逆効果。

3. **時間ステップ数 nt やウィンドウ長**  
   - nt を増やしても最適帯は大きく変わらず（400〜700）。  
   - ウィンドウが長大になるとキャッシュ効率・バッファ容量の影響が増える可能性があるため、追加検証が望ましい。

4. **ソルバー種別（DHCP / Adjoint / Sensitivity）**  
   - 現状の測定では 3 ソルバーとも同じ最適帯に収まる。  
   - これは同じ 3 次元アクセスパターンと前処理を共有しているためと考えられる。

## 4. 推奨設定（現状の格子・スレッド構成）

| ケース | スレッド数 | 推奨 basesize | 備考 |
|--------|------------|---------------|------|
| 標準（格子 80×100×20, nt≦100） | 4 | **600** | 最速構成。500 も性能差 1% 以下で安定。 |
| 2 スレッド運用 | 2 | 600〜800 | 600 と 1000 の差は 2% 程度。 |
| 8 スレッド運用（4コア以上の CPU が必要） | 8 | 500〜600 | 8 スレッド自体の効率が低い。 |
| basesize 非推奨値 | — | **1**, **2000**, **5000** | オーバーヘッド支配／粒度過大で大幅に遅い。 |

## 5. 追加検証の提案

現行データは特定の問題サイズと CPU 構成に偏っているため、以下の追加測定を行うとガイドラインの汎用性が高まる。

1. **格子サイズ依存性**  
   - 小規模（例: 40×50×10）と大規模（例: 200×200×40）を測定し、basesize が N にどうスケールするか確認。

2. **大ウィンドウ／長時間シリーズ**  
   - window=71, overlap=17, CGM≥3 の構成で basesize を振り、本番想定の設定を検証（Phase 5.2 Step3 の残課題）。

3. **異なる CPU アーキテクチャ**  
   - Intel/AMD CPU（8〜16 スレッド）で同じ測定を行い、スレッド数が大きい場合の最適帯を特定。

4. **ソルバー別解析**  
   - DHCP / Adjoint / Sensitivity の単体プロファイルを取得し、ソルバーごとの最適 basesize が一致するかを確認。

---

## 6. まとめ

- `basesize` はチャンクの最小粒度を制御し、オーバーヘッドと負荷分散のバランスを取るための重要パラメータ。  
- 現状の測定では **basesize=400〜600** が広い条件で安全かつ高速。`base size ≥ 1000` で明確な性能劣化が確認されている。  
- 最適値は **総要素数・スレッド数・時間ステップ** などに依存するため、条件が大きく変わる場合は数ケースの試行は必要。  
- 汎用推奨値として、格子16万セル級・4スレッド環境では **basesize=600** を最初に試すことを推奨する。

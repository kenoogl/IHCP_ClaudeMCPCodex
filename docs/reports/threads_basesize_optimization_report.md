# スレッド数とbasesize最適化レポート

**作成日**: 2025年10月24日
**測定対象**: DHCP単体ソルバー（10ステップ）
**格子サイズ**: 80×100×20 (N=160,000セル)

---

## エグゼクティブサマリー

スレッド数（2/4/8）とFLoops basesizeパラメータ（400/500/600/1000/2000/5000）の組み合わせ18パターンを体系的に測定し、最適な並列化設定を特定しました。

### 主要な発見

1. **全体最適値**: **4スレッド、basesize=600が最速** (4.88秒) ⭐⭐⭐
2. **スレッド数の影響**: 8スレッドは4スレッドより遅い（CPU 4コアのため）
3. **basesizeの影響**: basesize≥2000で性能が大幅に低下
4. **最適範囲**: basesize=400-600が全スレッド数で安定して高速

## 理論的考察

### basesizeの最適値の導出

**理論式**:
```
最適basesize ≈ 総要素数 / (スレッド数 × k)
```

**実測値との比較**:
```
総要素数: 160,000
スレッド数: 4
k: 不明（経験的に決定）

理論式: basesize ≈ 160,000 / (4 × k)
実測最適値: 600

→ k ≈ 160,000 / (4 × 600) = 66.7
```

**解釈**: 各スレッドが約67個のチャンクを処理するのが最適

### 並列化オーバーヘッドの分析

#### オーバーヘッドの内訳

1. **タスクスケジューリング**: basesizeが小さいほど増加
2. **キャッシュミス**: basesizeが大きすぎると増加
3. **スレッド同期**: スレッド数が多いほど増加

**4スレッドでの測定結果から**:
```
basesize=400: 5.06秒 → スケジューリングオーバーヘッド +0.18秒（+3.7%）
basesize=600: 4.88秒 → 最適バランス
basesize=1000: 6.48秒 → 粒度過大 +1.60秒（+32.8%）
```

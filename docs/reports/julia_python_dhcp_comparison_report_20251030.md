# Julia版 vs Python版 DHCP計算性能・精度比較レポート

**作成日**: 2025年10月30日
**対象**: DHCP（直接熱伝導問題）ソルバーの実装比較
**目的**: 同一条件でのJulia版とPython版の性能・精度検証

---

## 1. エグゼクティブサマリー

### 主要な発見

1. **Python版が圧倒的に高速**: 1スレッド比較で **15.2倍高速** (1.99秒 vs 30.21秒)
2. **Julia版の並列化効率が優秀**: 並列化効率150.8%（スーパーリニア）
3. **計算精度は同等**: RMS残差差異0.04%（実用上同一）
4. **前処理の効果が顕著**: Jacobi前処理により反復回数が **3.81倍削減**

### 推奨事項

- **短時間計算（～100ステップ）**: Python版を推奨（絶対速度優位）
- **大規模計算**: Julia版の並列化効率を活かして選択可能
- **今後の改善**: Julia版にJacobi前処理を実装することで大幅な高速化が期待できる

**低効率の要因**:
- CGソルバーの主要ループがNumba並列化の対象外

### 4.3 前処理の効果分析

#### Julia版：diagonal前処理の逆説

**反復回数削減**:
- none → diagonal: 884回 → 737回（**16.6%削減**）
- 削減倍率: 1.20倍

- 1スレッド: 30.21秒 → 32.62秒（**8.0%増加**） ❌

- 1反復あたりの時間: 34.2ms → 44.3ms（**29.5%増加**）

- マトリクスフリー実装では対角前処理の効率が低い

**結論**: Julia版のdiagonal前処理は**逆効果**

**反復回数削減**:
- Julia版(none)比較: **74.4%削減** (884回 → 232回)
- Julia版(diagonal)比較: **68.5%削減** (737回 → 232回)
- 削減倍率: **3.18～3.81倍**

**実行時間への影響**:

- 行列形式実装では前処理の適用が効率的

**前処理の原理**:
- Jacobi前処理は対角行列による単純な前処理
- システム行列の条件数を改善
- 収束速度を大幅に向上

**Julia版との差の要因**:
1. **実装方式の違い**:
   - Python版：行列形式 → 前処理が効率的
   - Julia版：マトリクスフリー → 毎反復で対角要素を再計算
2. **前処理の品質**:
   - 同じdiagonal/Jacobi前処理でも反復回数に3.18倍の差
   - Python版の実装がより効果的な可能性

## 6. 実装方式の比較

### 6.1 Julia版の特徴

**利点**:

- Jacobi前処理により反復回数が少ない

**欠点**:
- 疎行列構築のメモリオーバーヘッド
- 並列化効率が低い（29.3%）
- メモリ使用量が多い

平均: 30.21秒 / 9ステップ = 3.36秒/ステップ

Julia版が遅い理由:
1. **前処理なし**: 収束に多くの反復が必要
2. **マトリクスフリー**: 毎反復で行列ベクトル積を再計算
3. **1スレッド時のオーバーヘッド**: 並列化フレームワークのコスト

## 8. 並列化詳細分析

### 8.1 Julia版の並列化戦略

**並列化対象**:
- 熱物性値計算（ρ, Cp, k）
- 行列ベクトル積（Ax）
- 前処理適用（現在はnoneなので未実装）
- 境界条件適用

**並列化手法**:
```julia
@floop ThreadedEx(basesize=600) for k in 1:nk
  # 計算処理
end
```

**最適化結果**:
- basesize=600が最適（スレッド数×basesize最適化実験の結果）
- スーパーリニア高速化達成（150.8%）

### 8.2 Python版の並列化戦略

**並列化対象**:
- 熱物性値計算（ρ, Cp, k）
- 一部の配列操作

**並列化手法**:
```python
@njit(parallel=True)
def compute_properties(...):
    for k in prange(nk):
        # 計算処理
```

**並列化の実態（実測）**:
- **Numba並列化**: 有効（NUMBA_NUM_THREADS=4で制御）
- **OpenBLAS並列化**: ほぼ効果なし（疎行列演算が主体のため）
- 並列化効果: 1.97秒 → 1.66秒（OPENBLAS=1で測定）
- 純粋なNumba効果: 1.19倍（29.8%の並列化効率）

**制約事項**:
- CGソルバーの主要ループは並列化されていない
- 疎行列演算はSciPyが実行（OpenBLASバックエンド）だが、疎行列では並列化効果が限定的
- NUMBA_NUM_THREADSで並列度を制御
- OPENBLAS_NUM_THREADSでBLASスレッド数を制御可能（但し効果は小さい）

## 12. 結論

### 12.1 主要な発見

1. **Python版が現時点で最も高速**
   - Jacobi前処理の効果により反復回数が圧倒的に少ない（232回）
   - Julia版(none)比較: 1スレッドで**15.2倍**高速、反復回数**3.81倍削減**
   - Julia版(diagonal)比較: 1スレッドで**16.6倍**高速、反復回数**3.18倍削減**

2. **Julia版diagonal前処理の逆説**
   - 反復回数は16.6%削減（884回 → 737回）
   - しかし実行時間は**増加**（30.21秒 → 32.62秒）
   - マトリクスフリー実装では前処理のオーバーヘッドが大きい
   - **結論**: Julia版ではdiagonal前処理は**逆効果**

3. **Julia版は優れた並列化効率を示す**
   - 並列化効率143.6～150.8%（スーパーリニア）
   - 前処理の有無に関わらず並列化効率は優秀
   - 大規模計算・多コア環境での潜在能力が高い

4. **計算精度は同等**
   - RMS残差差異0.04%（0.00111 K）
   - 両実装とも数値的に安定で信頼性が高い

### 12.2 実用上の推奨

**現時点での推奨**:
- **短～中期的計算（～1000ステップ）**: Python版
- **大規模・長時間計算**: 前処理実装後のJulia版を待つか、現状でも並列環境ならJulia版も選択肢

**将来的な展望**:
- Julia版にJacobi前処理を実装すれば、1スレッドで6～8秒程度が期待される
- この場合、Python版の1.70秒（4スレッド）に近づき、並列化効率の差で逆転の可能性

### 12.3 技術的洞察

**前処理の重要性**:
- 前処理の有無が性能に与える影響は極めて大きい（3.81倍の差）
- 適切な前処理選択が最も重要な最適化要素

**並列化の課題**:
- Python/NumbaではCGソルバー内部の並列化が困難
- Julia/FLoopsは並列化が容易だが、前処理なしでは反復回数が多い

**実装方式の特性**:
- マトリクスフリー（Julia）: メモリ効率良、並列化容易、但し計算コスト高
- 行列形式（Python）: 実装簡単、前処理適用容易、但しメモリ消費大

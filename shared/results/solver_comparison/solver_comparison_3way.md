# CGMソルバー3方向比較レポート: PCG+none vs PBICGSTAB!+none vs PBICGSTAB!+GS

**実行日時**: 2025年10月21日
**テスト条件**: 10ステップ、フルサイズ（80×100×20格子）、CGM反復1回
**ブランチ**: sliding-window-validation

## 📋 使用スクリプトとコマンド

**テストスクリプト**: `julia/scripts/run_10steps_fullsize_test.jl`

**実行コマンド**:
```bash
# PCG + 前処理無し
julia --project=julia julia/scripts/run_10steps_fullsize_test.jl --solver pcg --precond none

# PBICGSTAB! + 前処理無し
julia --project=julia julia/scripts/run_10steps_fullsize_test.jl --solver pbicgstab --precond none

# PBICGSTAB! + Gauss-Seidel前処理
julia --project=julia julia/scripts/run_10steps_fullsize_test.jl --solver pbicgstab --precond gs
```

## 💡 推奨設定とベストプラクティス

### ✅ 推奨設定: **PCG + 前処理無し**

**推奨理由**:
1. ✅ **圧倒的最速**: 次点より17.4%高速
2. ✅ **優れた収束安定性**: 全ソルバー・全ステップで収束成功
3. ✅ **低い1反復コスト**: 最もシンプルで高速な反復
4. ✅ **予測可能な性能**: 反復回数の変動が最小（11.3%）
5. ✅ **同等の精度**: 他の構成と実質的に同じ結果
6. ✅ **実装が単純**: 前処理不要でメンテナンス容易

### 各構成の適用シーン

#### ✅ PCG + none（最推奨）
- スライディングウィンドウ計算（本テスト条件）
- 実時間処理が必要な場合
- 安定した性能が求められる場合
- 実装の単純さを重視する場合

#### ⚠️ PBICGSTAB! + none（条件付き推奨）
- メモリ制約が極めて厳しい場合（反復回数35%削減）
- 非対称性が強い問題（本問題は対称的）
- 未収束警告を許容できる場合

#### ❌ PBICGSTAB! + GS（非推奨）
- **推奨しない**: 前処理効果がコストで相殺される
- 反復回数は88%削減されるが、総実行時間では最遅
- 前処理オーバーヘッドが大きすぎる（1反復10.5倍遅い）

## 📝 技術的考察

### なぜPCG+noneが最速か？

1. **アルゴリズムの単純性**
   - PCG: 1反復あたり1回のマトリクス-ベクトル積のみ
   - PBICGSTAB!: 1反復あたり2回のマトリクス-ベクトル積 + 複雑な更新式
   - 前処理無し: オーバーヘッドゼロ

2. **対称正定値問題への最適化**
   - 熱伝導方程式は対称正定値行列を生成
   - PCGは対称性を活用した最も効率的なアルゴリズム
   - PBICGSTAB!は非対称問題用（本問題では過剰な機能）

3. **キャッシュ効率**
   - PCGの単純な演算パターンはCPUキャッシュに優しい
   - 前処理無しはメモリアクセスが最小

### なぜGauss-Seidel前処理が遅いか？

1. **前処理コストが大きすぎる**
   - 各CG反復ごとにGauss-Seidel反復を実行
   - 順次依存性のためベクトル化・並列化が困難
   - 1反復時間が10.5倍に増加

2. **反復回数削減が不十分**
   - 反復回数88%削減は大きいが、前処理コストを相殺できない
   - 前処理で1反復コストが10.5倍になるため、反復回数を90%以上削減しないと効果なし

3. **メモリアクセスパターンの悪化**
   - Gauss-Seidel法は順次アクセスが必要
   - キャッシュ効率が悪化

### 実用的トレードオフの数値

| 構成 | 反復回数 | 1反復コスト | 総時間 | 評価 |
|-----|---------|-----------|-------|------|
| PCG + none | 2437回（基準） | 0.0087秒/回（基準） | 24.43秒 | ✅ 最適 |
| PBICGSTAB! + none | 1585回（-35%） | 0.0165秒/回（+90%） | 29.23秒 | ⚠️ 可 |
| PBICGSTAB! + GS | 292回（-88%） | 0.0910秒/回（+946%） | 29.75秒 | ❌ 不可 |

**結論**: 反復回数削減よりも1反復コスト削減が重要

## 🚀 今後の最適化方向

### 優先度高
1. **PCG + 軽量前処理の検討**
   - Jacobi前処理（対角スケーリング）
   - Gauss-Seidelより軽量で並列化可能
   - 反復回数削減と前処理コストのバランスが期待できる

### 優先度中
2. **適応的許容誤差の導入**
   - 初期ステップでは緩い許容誤差（rtol=1e-4）
   - 後期ステップで厳しい許容誤差（rtol=1e-8）
   - 総反復回数削減の可能性

3. **GPU並列化の検討**
   - PCGの単純な演算パターンはGPU化に有利
   - 大規模問題での更なる高速化

### 優先度低（非推奨）
4. **Gauss-Seidel前処理の改良**
   - Red-Black Gauss-Seidel（並列化可能）
   - しかし本問題では前処理効果が低いため優先度低

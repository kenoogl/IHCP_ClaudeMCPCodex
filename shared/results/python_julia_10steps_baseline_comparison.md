# Python-Julia 10ステップベースライン性能比較

**測定日時**: 2025年10月14日
**目的**: Julia版Phase 1性能改善の基準となるPython版ベースライン性能を測定し、公平な比較を実施

## 測定概要

### テスト条件（完全一致）
- **格子サイズ**: 80×100×20 (N=160,000格子点)
- **時間ステップ**: nt=10, dt=0.001s
- **CGM反復回数**: 1回（性能測定用）
- **CG許容誤差**:
  - DHCP: rtol=1.0e-6
  - Adjoint/Sensitivity: rtol=1.0e-8
- **CG最大反復数**: 20,000
- **測定データ**: `T_measure_700um_1ms.npy`（共通）

### 実行環境
- **OS**: macOS (Darwin 24.6.0)
- **CPU**: Apple Silicon
- **Python**: 3.12.7 (Numba 0.60.0)
- **Julia**: 1.11.7

## 重要な発見

### 1. Julia版が圧倒的に遅い理由

**現在のJulia版の主要ボトルネック（推定）**:

1. **CG法の反復回数が多い**
   - Python版: 詳細不明だが、3.77秒で完了
   - Julia版: 平均500-700回/ステップ（`performance_22fde2d.md`より）
   - CG反復回数の差が性能差の主因と考えられる

2. **前処理の効果の差**
   - Python版: 行列ベース、効率的な前処理
   - Julia版: マトリクスフリーPBICGSTAB!、Gauss-Seidel smoother
   - マトリクスフリー実装の収束性が劣る可能性

3. **メモリアクセスパターン**
   - Julia版はPhase Aでメモリレイアウト最適化済み
   - しかし、まだPython版ほど最適化されていない可能性

### 2. Python版の並列化が効かない理由

10ステップという小規模問題では：
- JITコンパイルのオーバーヘッド
- スレッド生成コスト
- メモリアクセスの競合
- キャッシュミス増加

これらが並列化の効果を打ち消している。

**参考**: `docs/reports/benchmarks/baseline_benchmark_20251002.md`では357ステップで測定しており、大規模問題では並列化の効果が大きい可能性がある。

### 3. Julia版の改善余地

**Phase 1で27.34%改善したが、まだPython版の150倍遅い**

残りの改善余地：
1. **CG法の収束改善**（最優先）
   - ILU前処理導入（Phase 2.2提案）
   - 初期推定値改善
   - 適応的収束判定

2. **メモリ最適化**
   - メモリプール導入（Phase 2.4提案）
   - キャッシュ効率改善

3. **並列化**（Phase 2提案）
   - BLAS並列化
   - マルチスレッドCG
   - ただし、10ステップでは効果限定的

4. **GPU対応**（Phase 3提案）
   - CG法全体のGPU実装
   - 大規模問題で効果大

## 結論と推奨事項

### 現状認識

1. **Julia版は依然としてPython版の150倍遅い**（Phase 1完了後）
2. **Phase 1で27.34%改善したが、まだ不十分**
3. **Python版との性能差の主因はCG法の収束性**

### 推奨戦略

**最優先課題**: CG法の収束改善

1. **Phase 2.2 ILU前処理の実装**（最優先）
   - CG反復回数を50-70%削減目標
   - Python版と同等の収束性を目指す
   - 期待効果: 100-150倍改善（Python版の1.5-2倍程度まで）

2. **収束性の詳細分析**
   - Python版とJulia版のCG反復回数比較
   - 前処理の効果測定
   - 初期推定値の影響調査

3. **メモリ最適化**（Phase 2.4）
   - メモリプール導入
   - キャッシュ効率改善
   - 期待効果: 15-25%改善

4. **並列化は後回し**
   - 10ステップ問題では並列化の効果が限定的
   - 大規模問題（357ステップ）で再評価

### 目標設定

| フェーズ | 目標時間（10ステップ） | Python版との比 | 改善率 |
|---------|----------------------|--------------|-------|
| ベースライン（22fde2d） | 1,072秒 | 257倍 | - |
| Phase 1完了（tuning7） | 779秒 | 187倍 | 27.34% |
| **Phase 2目標** | **10-20秒** | **2.4-4.8倍** | **98-99%** |
| 理想（Python版同等） | 4秒 | 1倍 | 99.6% |

**現実的な目標**: Phase 2完了時点で10-20秒（Python版の2.4-4.8倍）
